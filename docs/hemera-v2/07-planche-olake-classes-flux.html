2 La chronologie exactly-once — et ses deux crashs

Une seule règle : la source n'est acquittée qu'après la publication de l'édition qui la couvre. Tout le reste en découle.

⓪ curseur← édition N-1
① extract bornéchunks ∥ · WAL → cible · offsets
② stagingbranche WAP · dédup i/c
③ publishédition N (curseur inclus)
④ ack sourceslot / consumer group
⑤ lignageOpenLineage → Catalog
💥 crash avant ③rien n'existe (WAP) — re-run depuis le curseur de l'édition N-1 ; les chunks déjà commités sont sautés (E4) ; le WAL/les offsets ne sont pas acquittés, donc rien n'est perdu
💥 crash entre ③ et ④l'édition N existe mais la source ne le sait pas — recovery borné : rejouer jusqu'au curseur de l'édition N exactement (épinglé, anti-dépassement E7), dédupliquer par plage, puis acquitter — zéro doublon, zéro trou
Les deux crashs sont les SEULS cas possibles — et les deux convergent vers le même état final. C'est la propriété qu'OLake démontre pour Postgres (E7) et que notre modèle d'éditions étend à Kafka (E11 résolu).

3 Où passe chaque source — les quatre étages du même manifeste

L'étage moteur est un placement décidé à la compilation du manifeste — jamais une API différente pour l'auteur du flow.

SourceÉtage moteurWorkerCe qui atterrit
DB volumineuse · CDC log-based (PG/MySQL/Oracle…)③ OLake wrappé (Go + sidecar Java)el-cdcéditions = plages de LSN · colonnes _hemera.op/_cdc_lsn · vue « état courant » générée
Kafka / fluxnatif (kind STREAM — publish-then-commit)eléditions = plages d'offsets · replay exact par plage
API SaaS · long tail (Jira, HubSpot…)② dlt (E par dlt, L par le lake)eléditions incrémentales à curseur
JDBC léger · fichiers · Sheets① catalogue natif (spec + discover → no-code S9)elfull_refresh / append / merge
Tout le reste④ @source Python libreelle runtime fait le L (WAP), l'auteur fait le E
La règle d'or du wrap (identique à dbt/SQLMesh/MLflow) : l'outil tiers travaille à l'intérieur de la frontière — entrées gouvernées, écritures sur staging, publication par le flow, provenance dans l'édition. Changer d'étage moteur (natif → OLake quand la volumétrie monte) ne change ni le manifeste, ni les écrans S8/S9, ni le lignage — c'est un placement, comme le backend d'un embedding.
