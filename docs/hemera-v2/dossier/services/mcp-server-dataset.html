Découvrir les datasets et sélectionner les structures pertinentes

Comportement observé

Les outils listent les datasets, recherchent leurs structures et proposent métadonnées et schéma pour un dataset précis. La découverte lit l’API data-serve paginée. Les noms ou identifiants sont résolus dans le scope autorisé ; absence de données, credential absent et refus backend ont des formes d’erreur distinctes.

Dépendances et échanges

Comportement cible proposé

MCP/Catalog Rust sert découverte et schémas avec édition et droits de découverte explicites.

Migration de cette capacité

Un dataset hors scope n’apparaît ni dans le choix ni dans les suggestions ; toutes les pages utilisent la même édition.

MCPD-02Cible non qualifiée

Transformer une question en SQL de lecture vérifié

Comportement observé

database_research_tool récupère des schémas et exemples puis appelle un générateur SQL. La chaîne travaille actuellement en dialecte Trino/Cleyrop, vérifie que la requête est en lecture seule et détecte les colonnes absentes avant EXPLAIN et exécution. Le SQL généré est donc une proposition soumise à plusieurs contrôles et non une autorité sur les droits.

Utilisateurs et rôles

Analystes et agents conversationnels.

Interfaces dans le code

MCP database_research_tool ; data-serve /datasets/sql/query ; EXPLAIN.

Données et états

Question, schémas récupérés, SQL et résultat structuré.

Dépendances et échanges

LLM, SQLGlot/dialecte Cleyrop, Trino via data-serve.

Comportement cible proposé

MCP/Query Rust remplace Trino ; le générateur reçoit le catalogue de capacités réel du moteur sans JVM et des entrées épinglées.

Migration de cette capacité

Établir un corpus NL/SQL et requalifier fonctions, types, agrégats et erreurs ; aucune parité Trino implicite.

Critère d’acceptation à exécuter

Une requête d’écriture ou colonne hors schéma est refusée avant exécution ; une lecture rejoint exactement les éditions déclarées.

MCPD-03Cible non qualifiée

Réparer les erreurs SQL avec un budget et une mémoire de session

Comportement observé

Une erreur transitoire rejoue le même SQL sans nouveau LLM ; une erreur déterministe peut provoquer une régénération. Les essais rejetés sont transmis au générateur et conservés en mémoire de session liée au caller et à la conversation. La répétition sans progrès arrête la boucle. Un budget partagé borne les réparations de parsing et les nouvelles générations ; les échecs connus reviennent sous forme structurée.

Utilisateurs et rôles

Agents autonomes et opérateurs de coûts.

Interfaces dans le code

_validate_and_execute_sql ; _run_with_transient_replay ; session_memory.

Données et états

Journal d’essais, classe d’erreur et mémoire de session ; pas de checkpoint de données.

Dépendances et échanges

Backend SQL, générateur LLM et configuration de budgets.

Comportement cible proposé

MCP Rust garde un budget global temps/tokens/exécutions et une mémoire isolée par mandat ; Audit corrèle les tentatives.

Migration de cette capacité

Rejouer erreurs temporaires, syntaxiques et répétitives ; mesurer appels au LLM et arrêter les boucles improductives.

Critère d’acceptation à exécuter

Une panne réseau ne déclenche pas une régénération ; deux échecs identiques arrêtent selon la règle ; une autre identité ne reçoit pas les essais de la session.

MCPD-04Cible non qualifiée

Restituer les résultats SQL et expliquer les réponses vides

Comportement observé

Les résultats ont une représentation structurée, Markdown et CSV, avec erreurs typées et rendu de null. Le chemin de recherche peut signaler un résultat vide, effectuer un comptage et rechercher des correspondances proches. Les endpoints de schéma et métadonnées ont une gestion d’erreur commune ; un échec partiel ne doit pas être pris pour un dataset absent.

Utilisateurs et rôles

Agents et interfaces de résultats.

Interfaces dans le code

Données et états

Dépendances et échanges

Data-serve et outils de rapprochement textuel.

Comportement cible proposé

Query/MCP Rust fournit réponses paginées et exports avec même pin d’édition ; EXPORT est un effet avec reçu quand conservé.

Migration de cette capacité

Comparer CSV, nulls, résultats vides et limites ; qualifier les probes de suggestions sans exposer de données hors droit.

Critère d’acceptation à exécuter

Un agrégat nul n’est pas confondu avec zéro ligne ; pagination et export gardent les mêmes données et autorisations.

MCPD-05Cible non qualifiée

Isoler le credential et le périmètre de lecture de chaque appel

Comportement observé

Le credential entrant accepte le Bearer, sans fallback vers les anciens headers API-token. Une délégation exige fresh_headers et utilise un backend interne plutôt que le parcours public normal. Les outils vérifient le scope des datasets ; le serveur monte les outils de recherche SQL et de structure sur MCP HTTP et propage les traces.

Utilisateurs et rôles

Orchestrateur, IAM et clients MCP.

Interfaces dans le code

UserCredential ; get_user_credential ; FastMCP server.

Données et états

Mandat/credential par requête ; contextes de transport et scope.

Dépendances et échanges

cleyrop_common.mcp_read, IAM et data-serve interne.

Comportement cible proposé

MCP/IAM Rust limite chaque mandat à lecture des éditions nommées ; le moteur SQL n’obtient aucun droit générique table.modify.

Migration de cette capacité

Migrer Bearer et délégation avec tests croisés d’identité, expiration et scopes.

Critère d’acceptation à exécuter

Un ancien header seul ne donne aucun droit ; une délégation révoquée bloque metadata, EXPLAIN et exécution.

Architecture et exploitation du service cible

Plan de contrôle Rust proposé

  • MCP/Catalog Rust sert découverte et schémas avec édition et droits de découverte explicites.
  • MCP/Query Rust remplace Trino ; le générateur reçoit le catalogue de capacités réel du moteur sans JVM et des entrées épinglées.
  • MCP Rust garde un budget global temps/tokens/exécutions et une mémoire isolée par mandat ; Audit corrèle les tentatives.
  • Query/MCP Rust fournit réponses paginées et exports avec même pin d’édition ; EXPORT est un effet avec reçu quand conservé.
  • MCP/IAM Rust limite chaque mandat à lecture des éditions nommées ; le moteur SQL n’obtient aucun droit générique table.modify.

Plan de données proposé

  • Découverte et requêtes de lecture bornées ; exécution dans Query autorisé.

Découpage du core Rust

  • mcp-dataset, sql-planner-guard, attempt-budget et result-rendering.

Identité, autorisation et isolation

  • SQL de lecture et preflight de schéma ; contrôle serveur d’accès toujours nécessaire.
  • Credentials sans repr et scope fixé indépendamment des suggestions du LLM.

Exploitation et reprise

  • Budgets de génération/exécution et erreurs structurées ; mémoire locale de session non assimilée à journal durable.
  • Tests de dialecte, erreurs et délégation présents, non exécutés.

Séquence de migration

  • Adapter chaque endpoint metadata/structured et préserver la pagination ; introduire pins d’édition dans le résultat.
  • Établir un corpus NL/SQL et requalifier fonctions, types, agrégats et erreurs ; aucune parité Trino implicite.
  • Rejouer erreurs temporaires, syntaxiques et répétitives ; mesurer appels au LLM et arrêter les boucles improductives.
  • Comparer CSV, nulls, résultats vides et limites ; qualifier les probes de suggestions sans exposer de données hors droit.
  • Migrer Bearer et délégation avec tests croisés d’identité, expiration et scopes.

Écarts et décisions encore ouverts

  • Le dialecte et les fonctions Trino doivent être requalifiés sur le moteur sans JVM.
  • Le contrat actuel n’établit pas un pin d’édition Iceberg ni une reprise de résultat après panne de serveur.
