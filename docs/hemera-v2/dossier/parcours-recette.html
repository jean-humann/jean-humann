    Contrat d’interface pour une édition stable

    • Le frontend conserve le contexte identité/projet/environnement/édition/version sémantique dans ses clés de cache et ses requêtes. Une bascule d’environnement invalide les appels pendants. Un tableau paginé doit afficher le pin de lecture, pas une valeur latest recalculée entre deux pages.
    • Les événements de progression utilisent une séquence rejouable ou imposent un rechargement complet. Un événement SSE perdu ne change pas l’autorité d’une publication. L’interface distingue PREPARED, AUDITING, VETOED, CONFLICT, PUBLISHED, ACK_PENDING et résultat de commit inconnu à réconcilier.
    • Les clients reçoivent des erreurs versionnées avec operation_id et informations suffisantes pour décider d’un retry. Un retry automatique n’est permis que lorsque l’idempotence du contrat le couvre. Annuler une tentative publiée ne promet pas de rétracter un ack ou une livraison externe.
